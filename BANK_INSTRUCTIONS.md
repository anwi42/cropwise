# CropWise — Bank Portal Instructions

## Overview
A separate portal for bank officers and insurance
companies to verify farmer data, assess loan
eligibility, verify crop loss claims and monitor
their loan portfolio risk.

## Portal URL
Bank officer accesses at: /bank
Completely separate from farmer portal at /

## Color Theme
Same indigo and white as farmer portal.
Primary: #4F46E5
Background: #FFFFFF
Surface: #F9FAFB

## User Type
Generic Bank Officer login.
No specific bank branding.

## Database Changes

### bank_officers table
```sql
CREATE TABLE bank_officers (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    phone VARCHAR(15) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    organization VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### yield_certificates table
```sql
CREATE TABLE yield_certificates (
    id SERIAL PRIMARY KEY,
    farmer_id INTEGER REFERENCES farmers(id),
    bank_officer_id INTEGER REFERENCES bank_officers(id),
    crop_type VARCHAR(100),
    predicted_yield_min DECIMAL(10,2),
    predicted_yield_max DECIMAL(10,2),
    confidence_score DECIMAL(5,2),
    soil_health_score INTEGER,
    document_hash VARCHAR(64),
    verification_code VARCHAR(32),
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### loan_eligibility_scores table
```sql
CREATE TABLE loan_eligibility_scores (
    id SERIAL PRIMARY KEY,
    farmer_id INTEGER REFERENCES farmers(id),
    bank_officer_id INTEGER REFERENCES bank_officers(id),
    total_score INTEGER,
    soil_health_points INTEGER,
    yield_consistency_points INTEGER,
    farm_size_points INTEGER,
    crop_risk_points INTEGER,
    weather_risk_points INTEGER,
    score_breakdown JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### claim_verifications table
```sql
CREATE TABLE claim_verifications (
    id SERIAL PRIMARY KEY,
    farmer_id INTEGER REFERENCES farmers(id),
    bank_officer_id INTEGER REFERENCES bank_officers(id),
    claim_date DATE,
    claimed_loss_amount DECIMAL(12,2),
    claimed_reason VARCHAR(100),
    weather_data_on_claim_date JSONB,
    yield_prediction_at_time JSONB,
    verification_result VARCHAR(20),
    verification_explanation TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## Backend APIs

### Authentication

POST /api/bank/register
- Takes: name, phone, password, organization
- Hashes password with bcrypt
- Saves to bank_officers table
- Returns: success + officer_id

POST /api/bank/login
- Takes: phone, password
- Verifies against bank_officers table
- Returns: success + officer_id or invalid credentials

### Feature 1 — Farm Verification

GET /api/bank/farmer/{farmer_id}
- Takes: farmer_id
- Fetches complete farmer profile:
  personal details, farm details,
  latest soil report and health score,
  crop history, yield prediction history,
  weather alerts history
- Returns: complete verified farm profile

GET /api/bank/farmer/search?phone={phone}
- Search farmer by phone number
- Returns: farmer_id + basic details
- Used by bank officer to find farmer

### Feature 2 — Yield Certificate

POST /api/bank/certificate/generate
- Takes: bank_officer_id, farmer_id
- Fetches latest yield prediction for farmer
- Fetches latest soil health score
- Fetches farm details
- Generates SHA-256 hash of all document content
- Generates unique verification code (UUID)
- Saves to yield_certificates table
- Generates PDF certificate containing:
  CropWise header with logo text
  Farmer name, village, district, state
  Farm size and soil type
  Current crop and variety
  Predicted yield range (min-max tons/acre)
  Confidence score
  Soil health score and zone
  Weather risk assessment for district
  Document hash embedded as text
  QR code linking to /bank/verify/{verification_code}
  Generated date and bank officer name
  Footer: "Generated by CropWise AI Platform"
- Returns: certificate_id + PDF download link

GET /api/bank/certificate/verify/{verification_code}
- Public endpoint — no login needed
- Fetches certificate by verification code
- Returns: certificate details + "AUTHENTIC" status
- Used when someone scans the QR code

GET /api/bank/certificate/{certificate_id}/pdf
- Downloads the generated PDF certificate

### Feature 3 — Loan Eligibility Score

POST /api/bank/loan/score
- Takes: bank_officer_id, farmer_id
- Calculates score out of 100 using this formula:

  Soil Health Points (max 25):
  Green zone = 25 points
  Yellow zone = 15 points
  Red zone = 5 points

  Yield Consistency Points (max 25):
  Has 2+ yield predictions = 25 points
  Has 1 yield prediction = 15 points
  No yield history = 5 points

  Farm Size Points (max 20):
  Above 10 acres = 20 points
  5-10 acres = 15 points
  2-5 acres = 10 points
  Below 2 acres = 5 points

  Crop Risk Points (max 15):
  Low risk crops (wheat, rice, maize) = 15 points
  Medium risk crops (onion, tomato) = 10 points
  High risk crops (cotton, sugarcane) = 7 points

  Weather Risk Points (max 15):
  No active weather alerts = 15 points
  1 alert = 10 points
  2+ alerts = 5 points

- Saves breakdown to loan_eligibility_scores table
- Returns: total score, breakdown per category,
  recommended loan amount range based on score,
  risk level (Low/Medium/High)

### Feature 4 — Crop Loss Claim Verification

POST /api/bank/claim/verify
- Takes: bank_officer_id, farmer_id,
  claim_date, claimed_loss_amount, claimed_reason
- Fetches yield prediction closest to claim date
- Calls Open-Meteo API for historical weather
  on claim date for farmer district
- Checks if claimed reason matches weather data:
  Flood claim → was there excess rainfall?
  Drought claim → was there dry spell?
  Frost claim → was temperature below 5 degrees?
  Pest claim → flags for manual review
- Returns:
  verification_result: VALIDATED / SUSPICIOUS / INCONCLUSIVE
  explanation: plain language reason
  weather_data: actual weather on claim date
  yield_data: predicted yield at that time
- Saves to claim_verifications table

### Feature 5 — Portfolio Risk Dashboard

GET /api/bank/portfolio/{officer_id}
- Returns all farmers who have been
  verified by this bank officer
- For each farmer returns:
  farmer_id, name, district, crop,
  latest soil health score,
  active weather alerts count,
  yield prediction,
  risk_level: LOW / MEDIUM / HIGH

Risk level calculated as:
LOW: soil green + no alerts + good yield
MEDIUM: soil yellow OR 1 alert
HIGH: soil red OR 2+ alerts OR no yield data

  High risk farmers count
  Pending claim verifications

### Farm Verification Page (/bank/dashboard/verify)
- Search bar at top:
  "Enter farmer phone number or ID"

  Soil health score with color zone

- Public page — no login needed
- Shows certificate details
- Large green checkmark + "AUTHENTIC DOCUMENT"

### Loan Score Page (/bank/dashboard/loan)
- Search farmer at top
- After finding farmer:
  Large score display (like soil health score)
  Score out of 100 with color:
  70-100 = Green (Low Risk)

  0-39 = Red (High Risk)

  Category | Points Earned | Max Points | Reason

### Claim Verification Page (/bank/dashboard/claim)
- Form fields:
  Farmer phone or ID (search)
  Claim date (date picker)

  Claimed reason (dropdown):
    Flood, Drought, Frost, Pest, Hailstorm, Fire
  "Verify Claim" button
- After verification:
  Large result badge:
  Green = VALIDATED
  Red = SUSPICIOUS
  Yellow = INCONCLUSIVE
  Explanation in plain language
  Weather data table for claim date
  Yield prediction at time of claim

### Portfolio Map Page (/bank/dashboard/portfolio)
- Leaflet.js map of India
- Each verified farmer shown as a pin:
  Green pin = Low risk
  Yellow pin = Medium risk
  Red pin = High risk
- Click any pin: shows farmer name, crop,
  risk reason, quick action buttons
- Summary stats below map:
  Total farmers, green count, yellow count,
  red count
- Filter by: district, crop type, risk level

## Important Rules
- Bank officers can only VIEW farmer data
  not edit it
- Every certificate has unique verification code
  stored in database
- Loan scores recalculate fresh every time
  not cached
- Claim verification always shows actual
  weather data as proof
- Portfolio map loads fast — cache farmer
  risk levels, refresh every 6 hours
